## How the system uses it (triage)

Thresholds chosen on validation: flag τ = 0.18 (human recall ≥ 0.95), direct handoff at P(human) ≥ 0.63 (precision ≥ 0.90), out-of-scope refusal at confidence ≥ 0.60 (precision ≥ 0.90).

- **Direct handoff** (no LLM call): 8/8 correct on test; it catches 8/24 human-route cases on its own.
- **Flagged to the agent** (possible human; the agent decides with `handoff_to_human` and the policy engine's own escalations): human cases reached directly or flagged 24/24; non-human messages flagged 25 (they still get a normal answer if the agent sees no reason to hand off).
- **Refused as out of scope** (no LLM call): 10/10 correct on test.

A flag costs nothing when it's wrong (the agent answers normally), so the recall target applies to it; the direct paths skip the agent, so they need high precision.

## Data and method

- `classifier_data/utterances.csv`: 627 utterances in 126 template families, about half Portuguese. **Model-drafted** (model-drafted (claude-opus-5-5); see classifier_data/README.md). The dataset has no Portuguese and its call transcripts use two fixed sentences, so it can't supply training text; its complaint categories and contact reasons informed the human-route topics.
- **Split:** `split.json`, frozen before any tuning; whole families only (paraphrases and translations never cross splits), stratified by route. Train 377 / validation 125 / test 125 rows.
- **Tuning on validation only:** for each feature set and C, τ from the recall constraint, then macro-F1 at that τ:

| Features | Best C | τ | Validation macro-F1 | Recall ≥ 0.95 |
|---|---|---|---|---|
| embedding | 1.0 | 0.16 | 0.559 | yes |
| tfidf | 1.0 | 0.23 | 0.461 | yes |
| both | 1.0 | 0.18 | 0.592 | yes |

- **History (honest account):** the first run used embeddings only and scored test macro-F1 0.691 against the baseline's 0.786, with human recall 1.00 but 32/101 unnecessary human routes (`report_v1_embeddings_only.json`). Adding character n-grams was prompted by reading that run's test errors, so this test split is no longer untouched by design decisions. The feature set, C and τ themselves were still chosen on validation only.
- **Baseline:** `baseline_rules.py`, accent-insensitive ES/PT keyword rules written from the route definitions.

## Limitations

- The utterances are model-drafted, not real customer messages; real traffic will be messier (typos, longer stories, several requests at once). The numbers measure the method on this data, not production accuracy.
- The test split is small (125 utterances, 24 of them human-route), so the intervals above are wide.
- Families were written by one author; phrasing styles may repeat across families even though no paraphrase crosses splits.
- The same author wrote the baseline's keywords, knowing the data's vocabulary; the baseline is probably flattered by that.
